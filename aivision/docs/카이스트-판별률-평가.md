# 카이스트 테스트베드 — 이미지 판별률 평가 (시험 항목 5)

시험 항목 5(사람·물류로봇 인식)는 데이터 100개를 학습된 모델로 분류해 정답과 비교하고,
**화면에 출력된 이미지 판별률**을 확인합니다.

```
이미지 판별률 = 일치 횟수 / 데이터 수 × 100        기준 95 % 이상
```

평가는 객체감지 플러그인이 합니다. 입구가 둘이고 판독 코어는 하나입니다 — 같은 세트를
돌리면 같은 숫자가 나옵니다.

| 입구 | 쓰는 곳 |
|---|---|
| 스크립트 `python evaluate.py /eval/<세트>` | 시험 당일, 콘솔 화면에 판별률을 띄울 때 |
| 플러그인 화면(11990) 맨 아래 **이미지 판별률 평가** | 결과 이미지를 넘겨 보며 틀린 것을 찾을 때 |

---

## 1. 판독은 실시간 화면과 똑같이 한다

평가용 판독기를 따로 만들지 않았습니다. 플러그인의 설정을 그대로 읽습니다.

- **모델** — '배치된 모델' 에서 **사용** 을 켠 공통 모델 전부 (지금 `AMR_detection_v2.onnx` + `person_yolo11m.onnx`)
- **클래스 표** — '클래스 관리' 에서 끈 클래스는 평가에서도 없는 것으로 칩니다
- **민감도** — '탐지 민감도' 의 최소 점수(conf)·겹침 기준(IoU)·최소 박스 크기
- **입력 크기** — 모델마다 모델 파일에 박힌 크기로 판독합니다. 지금 AMR(YOLO11m) 은 640, 사람(YOLO11m, COCO 사전학습)은 **1280**
  (QHD 화면에서 먼 사람이 640 으로 줄이면 10~15px 까지 작아져 거의 못 잡았기 때문입니다).
  결과의 `summary.json` 에 모델별 입력 크기가 남습니다

그래서 평가 전에 민감도를 바꾸면 평가 결과도, 관제 화면도 함께 바뀝니다. 시험 결과와
실제 화면이 달라질 수 없게 일부러 이렇게 묶었습니다.

모델 클래스는 평가 라벨로 옮깁니다: `AMR → AMR`, `person → Human`. 이 둘이 아닌 탐지(COCO
모델의 다른 클래스를 켜 둔 경우 등)는 평가에서 빼고, 몇 개를 뺐는지 결과에 남깁니다.

---

## 2. '일치' 의 뜻 — 객체 단위, IoU 0.5

한 이미지가 **일치** 이려면

1. 정답 객체(AMR·Human)가 **모두** 같은 클래스의 탐지와 IoU 0.5 이상으로 짝지어지고
2. 짝이 없는 탐지(헛탐지)가 **하나도** 없어야 합니다.

정답 객체가 없는 이미지는 탐지도 없어야 일치입니다. 짝짓기는 같은 클래스끼리 IoU 가 큰
순서로 하나씩(1:1) 합니다.

| 결과 이미지 표시 | 뜻 |
|---|---|
| 클래스 색 박스 `AMR 0.92` | 정답과 짝지어진 탐지 |
| 빨간 박스 `… FP` | 헛탐지 — 정답에 없는 것을 잡음 (클래스를 틀린 것도 여기) |
| 빨간 점선 `MISSED Human` | 놓침 — 정답인데 못 잡음 |
| 테두리 초록 / 빨강, 왼쪽 위 `OK` / `NG` | 그 이미지의 일치 / 불일치 |

---

## 3. 데이터 배치

호스트의 `EVAL_PATH`(기본 `C:/aivision-eval`)가 컨테이너의 `/eval` 입니다. 세트 하나가 폴더 하나입니다.

```
C:/aivision-eval/kaist/
  images/      cam3_0001.jpg …          평가할 이미지 (jpg·png)
  labels/      cam3_0001.txt …          정답. 이미지와 같은 이름
  classes.txt                           정답 클래스 이름, 한 줄에 하나 (예: AMR / Human)
```

- 정답 txt 는 **YOLO 형식**입니다. 줄마다 `클래스번호 cx cy w h` (0~1). CVAT·LabelImg·Roboflow 의
  'YOLO' 내보내기가 이 모양입니다. CVAT 내보내기(`obj_train_data/` + `obj.names`)도 그대로 받습니다.
- `classes.txt` 의 순서가 정답 txt 의 클래스 번호입니다. `person`·`사람`·`robot`·`물류로봇` 같은
  이름도 받아 AMR / Human 으로 맞춥니다. **없으면 0=AMR, 1=Human 으로 가정**하고 그 사실을
  결과에 경고로 남깁니다.
- 정답 파일이 **하나도 없으면** 판독만 합니다(판별률 없음). **일부만 없으면 멈춥니다** —
  정답 없는 이미지를 조용히 빼면 분모가 줄어 판별률이 부풀려지기 때문입니다.

플러그인 화면의 **세트 올리기** 로 폴더째 올려도 같은 자리에 같은 모양으로 놓입니다.
같은 이름의 세트가 있으면 받지 않습니다(옛 정답과 새 이미지가 섞이는 것을 막기 위해).

---

## 4. 시험 당일 — 스크립트로

```
cd aivision/deploy
docker compose exec mod-yolo python evaluate.py /eval/kaist
```

콘솔에 이미지마다 한 줄씩 진행이 나오고, 마지막에

```
모델   AMR_detection_v2.onnx (입력 640), person_yolo11m.onnx (입력 1280) (cuda)
임계값 conf 0.4 · 일치 IoU 0.5
AMR    맞춤 … · 놓침 … · 헛탐지 …
Human  맞춤 … · 놓침 … · 헛탐지 …
결과   /eval/kaist/results/20261106-122437
========================================================================
이미지 판별률 = 일치 97 / 데이터 100 × 100 = 97.0 %   (기준 95 % 이상 → 적합)
========================================================================
```

선택 인자: `--predict-only`(정답 없이 판독만), `--match-iou 0.5`, `--criterion 95`,
`--models a.onnx,b.onnx`(공통 모델 대신), `--map AMR=AMR,person=Human`.

## 5. 결과물

실행마다 새 폴더가 생깁니다 — `/eval/<세트>/results/<YYYYmmdd-HHMMSS>/`

| 파일 | 내용 |
|---|---|
| `annotated/*.jpg` | 박스·라벨을 그린 이미지 (2절의 표시) |
| `predictions/*.txt` | 판독 결과, 정답과 같은 YOLO 형식 + 신뢰도. 번호는 `predictions/classes.txt` 순서 |
| `results.csv` | 이미지별 판정·정답 수·탐지 수·맞춤·놓침·헛탐지 (엑셀에서 바로 열림) |
| `summary.json` | 판별률·적합 여부·클래스별 집계, 그리고 모델·임계값·장치·시각(재현 근거) |

플러그인 화면에서는 같은 결과를 격자로 보고(불일치만 거르기, 눌러서 크게 · ←/→ 로 넘기기),
**결과표 CSV**·**결과 묶음 ZIP**(위 폴더 통째)으로 내려받습니다.

## 6. 소스 코드 확인 (시험 항목의 세 가지 코드)

`aivision/modules/yolo/evaluate.py` 한 파일에 차례로 있습니다.

| 시험이 요구하는 코드 | 위치 |
|---|---|
| 데이터를 불러오는 코드 | `load_set()` — `find_images()`, `find_label()`, `load_class_names()`, `parse_yolo()` |
| 학습된 모델로 분류하는 코드 | `class Detector` — 플러그인의 `inference.load()` 와 같은 거르기 규칙 |
| 정답과 비교해 정확도를 내는 코드 | `match()`(IoU 짝짓기), `evaluate()`(집계·판별률), `rate_line()`(화면 출력) |

플러그인 화면 입구는 `eval_api.py` 이고, 판독·비교는 위 `evaluate()` 를 그대로 부릅니다.
`tests.py` 의 `test_evaluation()` 이 짝짓기·좌표 변환·클래스 이름 처리를 검사합니다.
